# goit-cs-hw-05

Домашнє завдання «Асинхронна обробка». Два незалежні скрипти.
Потрібен Python 3.11 або новіший (TaskGroup). Docker не потрібен.

## Встановлення на Mac

Розпакувати папку goit-cs-hw-05 на Desktop, потім у Terminal:

```bash
cd "$HOME/Desktop/goit-cs-hw-05"
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

У новому вікні Terminal повторно активувати `.venv`.

## Завдання 1: асинхронне сортування

```bash
python task_01/sort_files.py samples/source sorted_files
```

Аргументи source і output — обов'язкові. Шляхи з пробілами взяти в лапки.
Додатково: `--workers 8`, `--log-file sort_errors.log`.

Обхід `read_folder` рекурсивний і використовує асинхронний `anyio.Path`.
`copy_file` читає і записує байти через `anyio.open_file` блоками по 1 MiB.
Черга asyncio має обмежений розмір, а кількість workers обмежує кількість
одночасно відкритих файлів. Синхронні дискові операції AnyIO виконує
в робочих потоках, щоб не блокувати event loop. Асинхронність сама по собі
не гарантує прискорення на кожному диску.

Розширення нормалізуються до нижнього регістру: `.CSV` -> `csv`.
Використовується останнє розширення: `.tar.gz` -> `gz`.
Файли без розширення (також `.gitignore`) -> `no_extension`.

Очікуваний результат прикладу:

```text
sorted_files/
  txt/report.txt
  txt/nested/report.txt
  csv/nested/data.CSV
  no_extension/LICENSE
```

Відносна структура папок зберігається всередині групи розширення,
тому однакові назви в різних папках не конфліктують. Оригінали зберігаються.
Наявні файли призначення НЕ перезаписуються: лог містить FileExistsError,
інші файли продовжують копіюватися, підсумковий код завершення — 1.
Для повторної демонстрації використати нову output-папку.
Символічні посилання та спеціальні файли пропускаються з попередженням.
Source та output не можуть бути однією папкою або бути вкладеними одна в одну.
Помилки логуються і в консоль, і в sort_errors.log.

## Завдання 2: URL -> MapReduce -> графік

```bash
python task_02/mapreduce_words.py "https://www.gutenberg.org/files/1342/1342-0.txt" --top 10
```

Це приклад публічного тексту. За недоступності адреси використати інший
HTTP(S) URL зі звичайним текстом або локальну демонстрацію нижче.
HTML не очищається: для осмисленої статистики потрібен plain text.

Параметри: `--workers 4`, `--top 10`, `--timeout 30`,
`--chart top_words.png`, `--json word_counts.json`,
`--log-file analysis_errors.log`.

1. download_text завантажує текст із тайм-аутом і лімітом 20 MiB.
2. tokenize виділяє Unicode-слова; регістр і типи апострофів нормалізуються.
   Числа та підкреслення не вважаються словами, дефіс розділяє слова.
   Англійські й українські слова підтримуються; стоп-слова не відкидаються.
3. Map: `(слово, 1)`. ThreadPoolExecutor обробляє пакети по 1000 слів.
4. Shuffle: згрупувати значення за словом.
5. Reduce: підсумувати значення кожного слова (також через пул).
6. visualize_top_words зберігає горизонтальний PNG-графік топ-слів.
   Для однакової частоти використовується алфавітний порядок.

JSON містить URL, загальну кількість слів, кількість унікальних слів,
топ та всі частоти. PNG працює без графічного робочого столу (backend Agg).
На Mac зображення можна відкрити подвійним клацанням.
Помилки HTTP, мережі, декодування та запису логуються; код завершення — 1.
Кодування береться з HTTP charset; за його відсутності очікується UTF-8.
Текст, токени й проміжні пари зберігаються в пам'яті. Це навчальна
реалізація для обмежених текстів, не потоковий аналіз необмежених даних.
Пул потоків демонструє конкурентний MapReduce, але через GIL та накладні
витрати не гарантує прискорення обчислення частот у звичайній CPython.

## Демонстрація без зовнішнього сайту

```bash
python run_demo.py
```

Ця команда перевіряє сортування у тимчасовій папці, піднімає локальний
HTTP-сервер, завантажує samples/text.txt за HTTP URL і запускає другий
скрипт. Сервер автоматично зупиняється. Зберігаються top_words.png,
word_counts.json та demo_summary.json у корені проєкту.
Це реальне завантаження через HTTP, а не підміна завантаження читанням файла.
Зразки результатів у комплекті отримані цим способом у Linux.

## Тести

```bash
python -m unittest -v test_homework.py
```

Перевіряються: байтова точність копіювання (зокрема файл >1 MiB),
порожні файли, розширення у верхньому регістрі, файли без розширення,
однакові назви, захист від перезапису, вкладені output-папки,
відсутня source, символічні посилання, Unicode й апострофи,
точні частоти, пустий текст, PNG, справжній локальний HTTP та HTTP 404.

## Здача

У публічний репозиторій goit-cs-hw-05 завантажити вміст цієї папки,
зберігши папки task_01, task_02, samples. Не завантажувати .venv,
__pycache__ та службові логи. Обидва скрипти містять argparse та main-блок.
У LMS додати ZIP з назвою ДЗ5_ПІБ і посилання на репозиторій.

В умові згадано код MapReduce з конспекту. Оскільки сам конспект не надано,
тут використано самостійну реалізацію Map/Shuffle/Reduce з пулом потоків.
